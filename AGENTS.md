# Release rules — DuskGram

These rules are permanent. They describe how every DuskGram build is published
to the Telegram channel and to GitHub. Do not relax them without the owner
explicitly asking.

## 1. One bubble per release

All APKs for a build are posted as a **single album** (`sendMediaGroup`), with
the caption on the first item only.

- Implemented in `scripts/tg-upload.sh` (default behaviour).
- `--separate` exists for debugging only. Do not use it for real releases.
- Never post a second message that repeats what the album already says
  (no separate "downloads" post, no separate "notes" post).

## 2. Short caption

The caption is generated by `build.sh` and must stay minimal:

```
DuskGram <version>

• <what changed>
• <what changed>

GitHub release
```

- At most 5 bullets, pulled from commits made since the previous release tag.
- `Bump version` commits are filtered out.
- No branch name, no commit SHA, no timestamp, no ABI list, no file sizes,
  no repeated channel link, no "What's new / Downloads / Notes" headings.

If a release genuinely needs extra explanation (e.g. a signature change that
forces a reinstall), add **one** short warning line. Nothing more.

## 3. Publishing sequence

```bash
./build.sh --bump patch          # version only
./build.sh --apk-only            # incremental build, never clean
./build.sh --release-only        # GitHub release + assets
./build.sh --send-only           # album post to the channel
```

Then pin the album post and delete the previous release's post so the channel
shows exactly one current release.

## 4. Never clean

All builds go through `./build.sh` and stay incremental. No `clean`, no
`./gradlew clean`.
